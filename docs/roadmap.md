# Platform 路线图

- **状态：** 持续更新的文档
- **最后更新：** 2026-10-22
- **范围：** [`cyberverse-engine/platform`](../README.md)

本文档描述平台库的预期演进方向。它列出的是工作项，而不是承诺；随着渲染器和引擎集成需求逐渐明确，优先级和 API 细节可能发生变化。

## 愿景

`platform` 是 Cyberverse Engine 中唯一直接与操作系统交互的部分。它应当：

- 为窗口、原始输入、帧计时和按键映射提供一套小而统一的、与渲染器无关的 API；
- 向渲染器交付稳定的原生窗口描述，而不是自己创建图形设备或交换链；
- 为每个功能提供确定性的 headless 路径，使输入、计时和窗口状态逻辑无需显示服务器即可测试；
- 将后端相关代码隔离在 `backends/<backend>/` 之后，以 GLFW 后端作为参考实现；
- 保持低帧开销：输入和映射更新不得在热路径上分配内存或阻塞。

## 当前基线

当前代码是一个可工作的 GLFW + headless 基线。

| 领域 | 状态 |
| --- | --- |
| 核心接口 | `platform`、`window`、`raw_input_state`、`timer`、`key_mapping` 已实现。 |
| 后端选择 | GLFW 是编译期默认后端；headless 始终构建；SDL 是会在配置阶段报错的占位后端。 |
| GLFW 窗口 | `GLFW_NO_API` 窗口、resize/focus/input 回调、光标模式、HiDPI 帧缓冲缩放、原生句柄。 |
| Headless 窗口 | 队列化的 `inject_*` 事件、resize 回调、关闭请求、确定性的 `poll_events()`。 |
| 输入 | 键盘、鼠标按键、鼠标位置/增量、滚轮、UTF-8 文本、modifier 状态、逐帧边沿。 |
| 按键映射 | 命名 Action、多绑定、精确 modifier 匹配、鼠标按键绑定。 |
| 计时 | 单调 steady-clock 计时器，提供 delta、总时间和帧计数。 |
| 生命周期 | 窗口和计时器通过 release handler 保持 platform 存活。 |
| 验证 | 30 个 Catch2 测试、可选的真实 GLFW 窗口测试、按键映射基准。 |
| 平台覆盖 | macOS 已验证；Windows 和 Linux 的原生句柄路径已实现，但尚未纳入 CI。 |

### 已知限制

- 事件按窗口泵送。每帧轮询多个窗口会重新开始输入帧并丢失边沿；当前文档约定每应用帧只轮询一个窗口。真正的多窗口应用需要平台级事件泵。
- 窗口无法在运行时修改标题、移动、以编程方式调整大小、隐藏、最小化或切换全屏/无边框。没有显示器枚举或内容缩放变化通知。
- 输入缺少剪贴板、IME 组合输入、光标图像/位置控制、拖放、手柄和触摸/触控笔。
- 按键映射没有持久化、输入上下文（游戏/菜单）、轴绑定或冲突查询。
- 没有帧率控制、delta 钳制、暂停/时间缩放，也没有用于确定性计时测试的可注入时钟。
- SDL 后端有意未实现。
- 没有安装/导出 CMake 包、版本头、示例程序、CI 矩阵或生成的 API 文档。

## 里程碑

| 里程碑 | 主题 | 退出标准 |
| --- | --- | --- |
| v0.2 | 事件泵、窗口生命周期、计时 | 每帧一次平台轮询即可保证多窗口输入正确；窗口状态可在运行时控制；计时器可测试、可配置。 |
| v0.3 | 输入完整性与映射 | 覆盖桌面输入能力（剪贴板、IME、光标、拖放）；按键映射支持上下文和持久化。 |
| v0.4 | 可移植性、打包与质量 | CI 覆盖 macOS/Windows/Linux；可安装包和示例；性能和 sanitizer 门禁。 |
| v1.0 | 稳定 API 与引擎集成 | 公共 API 冻结；渲染器/原生句柄契约有文档；弃用策略生效。 |

SDL 后端有意不进入这些里程碑。它是 v1.0 之后的决策（见[待决问题](#待决问题)），而不是隐藏的 v0.4 任务。

### v0.2 — 事件泵、窗口生命周期、计时

**目标：** 让平台在具有多窗口和显示环境变化的真实桌面应用中保持正确。

- **平台级事件泵（P0）。** 新增 `platform::poll_events()`，为所有子对象开始一个输入帧，然后分发后端事件。保留 `window::poll_events()` 作为单窗口兼容路径（如果它会分裂帧状态则标记弃用）。Headless 窗口必须仍然每个平台帧只应用一次注入队列。
- **窗口生命周期（P0）。** 增加运行时标题、尺寸、位置、显示/隐藏、最小化/恢复/最大化、可调整大小、置顶，以及全屏/无边框控制。对未找到或不支持的操作返回明确错误，而不是静默无操作。
- **显示器与 DPI（P1）。** 枚举显示器（主显示器、列表、名称、工作区、内容缩放），查询窗口所在显示器，并报告内容缩放以及移动/调整大小变化。为 headless 后端增加模拟显示器模型，使 DPI 逻辑可测试。
- **计时器控制（P1）。** 增加最大 delta 钳制、暂停/恢复、时间缩放，以及供测试使用的可注入时钟。评估固定步长/帧率限制辅助器，但保持可选，让引擎掌握自己的帧策略。
- **错误与误用处理（P2）。** 将异步 GLFW 错误路由到错误处理器，而不是在初始化后丢弃。针对主线程误用，以及在可行时针对窗口销毁后使用，增加调试断言。
- **验收标准。** 单元测试覆盖多窗口边沿、窗口状态转换、headless 后端的显示器/DPI 变化，以及计时器钳制/注入；可选的 GLFW 冒烟测试覆盖窗口模式和 macOS 上的原生句柄有效性。更新文档和帧循环示例。

### v0.3 — 输入完整性与映射

**目标：** 覆盖桌面游戏/编辑器所需的输入能力，并让绑定易于维护。

- **剪贴板与文本（P1）。** 读取/设置 UTF-8 剪贴板文本；保持当前逐帧文本输入语义。在实现 Linux 剪贴板前，明确 X11 的所有权与选区语义。
- **IME（P1）。** 提供组合开始/更新/结束事件及候选窗口定位，同时将已提交文本保留在 `raw_input_state` 中。
- **光标（P1）。** 光标形状、自定义光标图像、光标位置查询/设置、光标限制在窗口内，以及独立于 `cursor_mode` 的可见性。
- **拖放（P2）。** 文件/路径拖放事件，并为拖放字符串定义明确的生命周期。
- **按键映射（P0）。** 输入上下文/层（游戏、菜单、文本输入）、序列化为稳定且无第三方依赖的文本格式、移动轴的按键/按钮组合，以及绑定冲突查询。保持 `update()` 零分配。
- **输入事件轨迹（P2）。** 通过 headless 后端录制和回放原始事件流，使边沿顺序回归可以固化为测试夹具。
- **验收标准。** 每个新增输入能力都有 headless 测试，包括剪贴板和 IME 队列；原生 IME 与光标行为有 GLFW 可选/手工测试；映射序列化有往返测试；`key_mapping::update()` 无逐帧分配。

### v0.4 — 可移植性、打包与质量

**目标：** 让库能够在当前工作区之外使用，并在三个桌面目标上可靠运行。

- **CI 矩阵（P0）。** 在 macOS、Windows 和 Linux 上构建并运行 headless 测试。在虚拟显示（Xvfb）以及可用的 macOS/Windows CI runner 上运行真实窗口测试；本地保持可选。
- **原生句柄验证（P0）。** 验证 Win32 `HWND`、X11 `Window + Display*` 和 Wayland `wl_display* + wl_surface*`，包括 HiDPI/分数缩放行为。记录每个后端哪些字段有效。
- **打包（P1）。** 增加安装/导出规则和 `cyberverse_platform` CMake 包、API/版本头，并记录最低 GLFW/GLM 版本。支持复用已有的 GLFW target（已通过 target 判断起步）。
- **示例（P1）。** 最小 GLFW 窗口循环、headless 确定性输入测试和按键重绑定示例。
- **文档与分析（P1）。** 生成 API 文档、后端与原生句柄选择的架构决策记录（ADR）、clang-tidy/sanitizer 运行，以及 CI 基准跟踪。
- **验收标准。** 干净的外部项目可以通过 `find_package`/`add_subdirectory` 使用；示例在 CI 中构建；三个后端的 headless 测试套件通过；macOS/Windows/Linux 窗口冒烟测试通过，或带有明确文档原因的跳过。

### v1.0 — 稳定 API 与引擎集成

**目标：** 冻结渲染器和引擎代码可以依赖的接口面。

- **API 冻结（P0）。** 确定事件泵、窗口状态、输入和计时 API；发布语义化版本策略，以及至少一个次版本的弃用过渡期。
- **渲染器契约（P0）。** 记录 Diligent 交换链的交接约定：macOS（`NSWindow*`/`NSView*`/`CAMetalLayer*`）、Win32（`HWND`）、X11 和 Wayland，包括线程与 resize 顺序要求。
- **确定性测试契约（P0）。** 明确 headless 后端保证的行为，以及有意保持后端差异的行为。
- **集成验证（P1）。** 一个小的 render-core/引擎示例：创建窗口、轮询输入、更新按键映射并渲染一帧。
- **发布检查清单（P0）。** API 评审、changelog、版本号更新、文档更新、格式化、无警告构建、headless 套件、GUI 冒烟套件、基准对比，以及最终确认 SDL 要么已实现、要么被明确拒绝。

## 横向工作

### 确定性

- 每个新增输入/窗口功能都应有 headless 队列或状态模型，而不是测试专用旁路。
- 测试优先使用可注入时钟和可注入事件源，而不是 `sleep`。
- 保持帧协议明确：每个平台帧一次 `begin_frame()`，然后分发事件，最后进行应用查询。

### 兼容性

- C++23；公共向量类型使用 GLM；启用时通过 `FetchContent` 固定 GLFW 3.4。
- GLFW 固定到已知版本；升级前测试升级路径，并记录依赖 GLFW 版本的原生访问器。
- macOS 是参考环境。Windows 10/11 与 Linux X11/Wayland 是支持目标，最终必须经过 CI 验证。

### 性能

基准应覆盖按键映射更新/查询和输入事件分发。热路径必须保持零分配；会分配内存的新功能（剪贴板、IME 字符串、拖放路径）必须明确所有权，并在空闲时避免逐帧分配。

### 测试

- 针对状态机、边沿顺序、计时和窗口状态的 headless 单元测试。
- 原生集成使用可选的真实窗口测试；默认测试运行绝不依赖显示器。
- 对难以用直接 API 调用表达的回归，使用基于夹具的事件轨迹。

### 文档

- 面向用户的 README，面向维护者的 `CLAUDE.md`/`AGENTS.md`。
- 每个公共符号都有 Doxygen。
- 本路线图用于排序和记录待决问题。
- 对约束渲染器或引擎的变更编写 ADR。

## 待办与评估中

这些事项有意不排期，需要先有明确的引擎或渲染器需求。

- 手柄/摇杆输入及映射数据库。
- 触摸与触控笔输入、压力/倾斜和手势识别。
- 高级 IME（行内组合渲染、候选窗集成）。
- 剪贴板图像和任意 MIME 负载。
- 系统主题/外观、电源/挂起和锁屏事件。
- 通知、托盘图标和文件对话框。
- 无障碍与屏幕阅读器桥接。
- 多席位/远程会话支持。
- Wayland 分数缩放细化与逐显示器 DPI 策略。
- SDL3 后端（仅当原生后端维护或平台覆盖需求证明其必要时）。

## 待决问题

1. **事件泵迁移：** `platform::poll_events()` 能否与 `window::poll_events()` 共存一个次版本，还是在 v1.0 前直接切换成本更低？
2. **GLFW 所有权：** 平台继续对 `glfwInit()` 做引用计数，还是允许应用移交已初始化的 GLFW 实例？后者会影响嵌入和多引擎实例。
3. **DPI 契约：** `width()`/`height()` 是帧缓冲像素。这对编辑器 UI 足够吗，还是平台还需要独立于帧缓冲 resize 事件的逻辑尺寸回调？
4. **映射持久化：** 小型行式格式是否足够，还是编辑器需要 JSON/资产管线集成？避免把 JSON 依赖引入 `platform`。
5. **手柄范围：** 手柄输入是平台职责还是更高层输入层？GLFW 与 SDL 的暴露方式差异很大。
6. **SDL 决策：** 什么具体的平台缺口值得引入第二个原生后端，是否应采用 SDL3？在此之前 SDL 保持受保护且未实现。
7. **帧策略：** `timer` 是否应负责固定步长累积和帧率限制，还是保持为纯测量服务、由引擎循环控制？
8. **线程模型：** 仅主线程规则是永久的，还是窗口创建/事件轮询需要显式的线程亲和 API？

## 非目标

- 创建图形设备、交换链或渲染器。`platform` 只移交原生窗口状态，不做其他事情。
- 音频、网络、文件系统、资产加载、ECS 或 UI 工具包功能。
- 在桌面 API 稳定前支持移动端、Web（Emscripten）和主机窗口。
- 插件/后端发现机制。后端在编译期编入，并在配置阶段选择。
- 用最小公分母 API 隐藏后端差异，从而让原生集成更困难。

## 路线图事项的完成定义

一个事项满足以下条件才算完成：

- 公共 API 有 Doxygen 文档，并记录错误/生命周期契约；
- headless 测试覆盖该行为（或该事项明确属于后端特定行为，并有可选的本地测试）；
- `clang-format`、无警告构建和完整 CTest 套件通过；
- 若约定变化，更新用户文档和 `CLAUDE.md`/`AGENTS.md`；
- SDL 编译期保护与 GLFW 关闭配置仍然可用；
- 性能敏感变更包含基准结果。
